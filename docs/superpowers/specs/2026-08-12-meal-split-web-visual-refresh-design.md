# Meal Split Web 视觉回归设计

## 目标

将当前独立 Web 版的视觉语言调整回原微信小程序的简洁、轻量、移动优先风格，同时保留网页版本的中英文切换、本地保存、消费记录、结算和复制功能。

本次工作是视觉与信息层级调整，不改变分账算法、金额计算、浏览器存储协议或公开 Web 的技术形态。

## 已确认的设计方向

采用“原小程序风格的网页优化版”（B）：

- 页面背景使用浅灰 `#f5f5f7`。
- 主要文字使用深黑 `#17191c`，辅助文字使用灰色 `#747b85`。
- 主要操作使用蓝色 `#1476f2`。
- 内容卡片使用白色、轻阴影和适度圆角。
- 移除当前版本的暖米色、橙色强调和过大的装饰性标题。
- 页面宽度收窄为移动优先的居中布局；桌面端保持约 640px 内容宽度，手机端保留原小程序相近的左右留白。
- 使用稳定的字体尺寸、行高和最大宽度，避免中文或英文标题出现突兀的孤立换行。
- 所有金额继续使用 `$` 符号；不增加货币选择，也不提示用户统一货币。

## 页面设计

### 1. 开始页

开始页沿用原小程序的结构：

1. 顶部可恢复本地账单的轻量提示卡。
2. 小号 eyebrow 文案，例如“开始新账单”。
3. 主标题和辅助说明，保持紧凑的移动端层级。
4. 分段选择：快速字母 / 输入姓名。
5. 白色设置卡片：参与人数步进器或姓名输入列表。
6. 深色主按钮“开始记账”。

分段控件、步进器、姓名输入和按钮均保持可触摸尺寸，并在桌面端保持同一视觉比例。

### 2. 账单页

账单页采用原小程序的主流程结构：

1. 顶部显示参与人数 eyebrow、标题和右侧“＋ 记一笔”蓝色按钮。
2. 中文标题固定为两行：

   ```text
   今天
   消费了多少
   ```

   英文使用自然的一行标题：`Today’s spending`。
3. 总消费使用深色大卡片，金额作为核心视觉信息，显示 `$`。
4. “消费明细”标题和笔数位于明细卡片上方。
5. 每笔消费的结构固定为：

   ```text
   晚餐   Alex 付款                 $86.00
          全部参与
   ```

   消费名称字号最大；付款人使用较小、较浅的辅助文字；参与方式位于下一行并使用辅助文字；金额固定右对齐。
6. 无消费时显示简洁空状态卡，点击卡片或“记一笔”均可打开编辑器。
7. 底部保留调整参与人和查看结算操作，但视觉上以主次按钮区分。

### 3. 记一笔编辑器

保留当前功能，视觉上改为原小程序的分组表单：

- 小屏幕使用底部弹出式 sheet，顶部有标题和取消操作。
- 大屏幕使用居中的白色/浅灰表单卡片，避免表单过宽。
- 金额使用大号输入区域和 `$` 符号。
- 付款人使用圆角选择标签。
- 分账方式使用分段控件；指定承担人使用选择标签。
- 备注单独放在卡片中。
- 保存消费使用深色全宽按钮。

### 4. 结算页

结算页沿用原小程序的重点信息层级：

1. 顶部标题“结算结果”和右上角“完成”。
2. 深色收款人 hero 卡片，展示收款人头像、统一收款说明、最终净收金额、总消费和人数。
3. 主收款人切换使用横向圆角标签，选中状态使用蓝色边框或浅蓝背景。
4. 转账区域使用“请按下面转账”标题和笔数。
5. 每条路线显示付款人头像、`谁 → 谁` 路由、辅助说明和右侧金额。
6. 复制结算文案使用主按钮，返回修改使用次按钮；复制失败时保留可手动复制的文本框。

英文页面保持相同结构，只替换文案，不改变视觉层级。

## 文案与双语规则

- 中文账单标题使用“今天 / 消费了多少”。
- 英文账单标题使用 `Today’s spending`，避免逐字直译造成不自然换行。
- 消费明细付款人使用“Alex 付款”；英文使用 `Paid by Alex`。
- “全部参与”英文使用 `Everyone`；指定参与人继续显示姓名列表。
- 账单页、编辑器、结算页、状态提示、错误提示和确认弹窗均继续从 `web/i18n.js` 取文案。
- 语言切换只改变文案和必要的布局适配，不改变业务状态。

## 技术边界

- 主要修改 `web/styles.css`、`web/app.js` 和 `web/i18n.js`。
- 不修改 `utils/money.js`、`domain/participants.js`、`services/settlement.js` 的业务算法。
- 不引入前端框架、构建工具或外部字体依赖。
- 保持 GitHub Pages 的静态部署方式和现有脚本加载顺序。
- 通过语义 HTML、可见焦点样式、足够的触摸目标和 `aria` 文案保持可访问性。

## 验证方式

实现后至少执行：

1. `npm test`，确认现有业务和 Web 测试全部通过。
2. `git diff --check`，确认没有空白错误。
3. 更新或新增 Web 布局测试，覆盖：
   - 中英文账单标题文案。
   - 中文标题两行结构。
   - 消费名称、付款人、参与方式和金额的层级结构。
   - 深色总额卡、主按钮和结算 hero 卡片的关键样式钩子。
4. 通过静态页面检查确认不存在微信小程序运行时依赖。
5. 在桌面宽度和窄屏宽度各检查一次开始页、账单页、编辑器和结算页，重点观察文字换行、按钮可见性和金额右对齐。

## 不在本次范围内

- 新增货币选择或汇率换算。
- 新增登录、云同步、多人实时协作或后端服务。
- 改变分账规则、收款人算法或金额精度规则。
- 重做品牌 Logo、插画或加入复杂动画。
