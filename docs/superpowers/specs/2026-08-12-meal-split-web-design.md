# Meal Split Web 开源版设计

日期：2026-08-12  
状态：已获用户确认，待用户审阅文档

## 1. 背景与目标

当前项目是一个微信小程序，核心能力是记录多人消费并生成结算路线。目标是把它改造成一个面向全球用户的独立 Web 应用，让用户无需微信、账号、服务器或安装步骤即可在浏览器中试用。

全球 Web 版需要：

- 支持中文和 English；
- 适配手机和桌面浏览器；
- 完全在浏览器本地运行；
- 使用 `$` 作为金额显示符号，不增加货币选择或汇率换算；
- 最大限度复用现有经过测试的金额和分账逻辑；
- 可部署到 GitHub Pages；
- 适合公开到 GitHub，方便用户试用和提交建议。

## 2. 已确认的范围

### 2.1 包含内容

- 开始页：创建或继续账单、设置参与人；
- 账单页：新增、编辑、删除消费记录；
- 结果页：显示参与人的付款、应承担、净额和转账路线；
- 中文/English 即时切换；
- 浏览器本地草稿保存；
- 浏览器剪贴板复制结算文案，并提供复制失败时的手动复制方案；
- 响应式布局、键盘操作、焦点状态和足够大的触控区域；
- 自动化测试和浏览器人工验收；
- 双语 README、MIT License、公开仓库和 GitHub Pages 发布说明。

### 2.2 不包含内容

- 微信小程序作为开源交付版本；
- 账号、云端同步、服务器、数据库或网络 API；
- 实时汇率换算；
- 货币选择器；
- 语音功能、联系人权限、位置权限、支付功能；
- 广告、统计、第三方分析和用户追踪；
- 强制提示用户在一张账单内统一使用某种货币。

金额以 `$` 前缀显示，例如 `$12.50`。这是界面显示约定，不代表应用执行美元换算或识别用户所在地区的货币。

## 3. 技术路线

采用原生 HTML、CSS 和 JavaScript，不引入 React、Vue 或构建框架。

选择理由：

- 浏览器可以直接运行，适合 GitHub Pages；
- 能复用现有普通 JavaScript 领域逻辑；
- 不需要用户安装依赖即可理解和试用；
- 对第一个开源项目更容易阅读和维护；
- 可以保持较小的依赖面和较低的供应链风险。

建议的代码边界：

```text
index.html                 Web 应用入口
src/
  app.js                   页面状态和路由协调
  components/              参与人、消费编辑器、结果卡片等 UI 组件
  i18n/                    中文和 English 文案
  storage/                 localStorage 适配器
  styles/                  响应式和可访问性样式
domain/                    参与人和分账领域逻辑
services/                  结算文案和浏览器服务适配
tests/                     Node.js 自动化回归测试
docs/                      设计和开发文档
```

实际实现可以根据迁移过程调整目录，但领域逻辑、浏览器服务和界面应保持分离。

## 4. 迁移策略

### 4.1 可复用内容

直接复用或小幅调整：

- `services/settlement.js` 的金额守恒、均摊、指定承担和收款路线算法；
- `utils/money.js` 的分/元解析和格式化基础；
- `domain/participants.js` 的参与人创建、校验和编辑保护；
- `services/share.js` 的结算文案生成原则；
- 现有金额、参与人、草稿和结算测试中的业务用例。

### 4.2 需要替换的内容

- 微信 WXML 页面替换为 HTML；
- WXSS 替换为普通 CSS；
- 微信页面生命周期和 `setData` 替换为浏览器状态更新；
- `wx.setStorageSync` 等接口替换为 `localStorage` 适配器；
- 微信复制接口替换为 `navigator.clipboard`，并提供手动复制降级；
- 微信弹窗替换为可访问的 HTML 对话框或等价的页面确认交互；
- 微信专用 `app.json`、`project.config.json` 和私有开发者配置不作为 Web 版本运行依赖。

## 5. 双语设计

- 首次打开根据浏览器语言自动选择中文或 English；
- 顶部提供明确的语言切换控件；
- 语言选择保存到浏览器，下次打开沿用；
- 所有按钮、标签、错误信息、确认操作、空状态、结果说明和复制文案都进入翻译字典；
- 用户填写的参与人姓名、备注和其他输入内容保持原样；
- 术语使用短而直白的英文，例如 `Participants`、`Expenses`、`Paid by`、`Split between`、`Settlement` 和 `Copy summary`；
- 金额统一使用 `$` 前缀和两位小数；
- 不因为语言切换而重置账单数据。

## 6. 数据与状态

浏览器本地保存当前账单，数据不离开用户设备。

基本流程：

1. 用户创建参与人并生成账单；
2. 每次新增、编辑或删除消费后保存到 `localStorage`；
3. 结果页调用领域层生成结算结果；
4. 切换语言只改变显示文案，不改变账单数据；
5. 用户完成账单后确认清除当前草稿并回到开始页。

异常处理：

- 没有草稿时显示空白开始页；
- 草稿损坏或版本不兼容时安全丢弃该草稿并重新开始；
- 金额、参与人和承担人校验失败时显示当前语言的明确错误；
- 剪贴板权限或浏览器能力不足时显示可选择、可手动复制的结算文本；
- 刷新或重新打开页面时尽力恢复最近一次有效草稿。

## 7. 测试与验收

自动化测试继续使用 Node.js 内置 `node:test`，覆盖：

- 金额解析、格式化和边界值；
- 全员均摊、指定承担、私享消费和余数分配；
- 多债权人结算路线和收款人切换；
- 参与人新增、编辑保护和重复校验；
- localStorage 保存、恢复、损坏草稿降级和完成清除；
- 中文/English 文案切换；
- 复制成功和降级路径；
- 页面关键操作和结果显示。

人工浏览器验收覆盖：

- 手机窄屏、普通手机和桌面宽屏；
- 2–20 位参与人；
- 长姓名、长备注和大金额；
- 新增、编辑、删除和刷新恢复；
- 中英文切换后继续操作；
- 结算路线、复制文案和完成清除；
- 键盘焦点、触控目标和基本读屏语义。

## 8. 开源与发布

公开仓库建议命名为 `meal-split-web`，最终名称以创建仓库时确认为准。

公开前必须：

- 添加双语 README，说明功能、在线试用、运行、测试、隐私和贡献方式；
- 添加 MIT License；
- 添加 `.gitignore`，排除 `.DS_Store`、微信私有配置、本地构建产物和编辑器临时文件；
- 不提交个人 AppID、微信开发者工具私有设置或其他本机信息；
- 检查 Git 历史和待提交文件，避免把私有配置带入公开仓库；
- 运行测试并完成可执行的浏览器验收；
- 推送到 GitHub 公开仓库；
- 配置 GitHub Pages，README 提供在线试用链接和反馈入口。

## 9. 完成标准

迁移完成的最低标准是：

1. 用户无需微信即可打开 Web 页面；
2. 中文和 English 两种语言的主要使用流程完整可用；
3. 现有核心算例在 Web 版中得到相同结算结果；
4. 刷新浏览器不会丢失有效草稿；
5. 复制失败时仍能取得结算文案；
6. 自动化测试通过，且已记录浏览器人工验收结果；
7. 公开仓库不包含私有配置或个人敏感信息；
8. GitHub Pages 可以打开并供他人试用。
